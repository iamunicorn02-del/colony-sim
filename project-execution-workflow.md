## Про superpowers:subagent-driven-development

Скилл изучен и намеренно **не используется**. Причины:
- Требует план-файл (`docs/superpowers/plans/*.md`) — у нас задачи в Taskmaster, не в файлах
- Двухэтапное ревью (spec + quality) — оверкилл для MVP с одним разработчиком
- `next_task` сам управляет порядком через граф зависимостей — дублировать это в план-файле нет смысла

Мы сделали **свой упрощённый вариант**: Taskmaster как источник задач + субагент-реализатор + Haiku-ревью + коммит.

## Стратегия выполнения задач

В начале сессии читаем этот файл и сразу начинаем выполнять задачи без вопросов к пользователю.

**Цикл на каждую задачу:**
1. `next_task` (Taskmaster MCP) — получить следующую задачу с учётом зависимостей
2. Прочитать `details` задачи — это спецификация; для воронки (#17–#21) читать `docs/ux/task-creation-funnel.md`
3. Для сложных backend-задач (#45+): сначала `expand_task` чтобы разбить на подзадачи
4. **Dispatch субагент-реализатор (Sonnet)** — передать: текст задачи + нужные файлы контекста + CLAUDE.md выжимку. Субагент реализует, прогоняет тесты, делает self-review
5. **Dispatch Haiku subagent для ревью** — передать: текст задачи (спек) + diff реализации. Проверяет соответствие спеку и явные баги
6. Если ревью нашло проблемы — субагент-реализатор фиксит (re-dispatch с описанием issues), до коммита
7. Коммит с понятным сообщением
8. `set_task_status(done)` в Taskmaster
9. Перейти к следующей задаче

**Почему субагент для реализации:** контроллер остаётся лёгким (не накапливает код в контексте) → больше задач за сессию до компрессии.

**Важно:** не останавливаться и не спрашивать пользователя между задачами. Продолжать до исчерпания лимитов контекста или выполнения всех задач.

## Ревью субагентом (Haiku)

Subagent model: `haiku` (быстрый, дешёвый)

Задача ревьюера: проверить реализованный код на:
- Соответствие спецификации задачи (details + testStrategy из Taskmaster)
- Явные баги или пропущенные edge cases
- Нарушения ограничений из CLAUDE.md (финансовые данные, GDPR, DAC7)

Ревью — блокирующее: задача не считается выполненной, пока issues не исправлены.
